# Сугроб (Snowdrift)

Осадки поверх рабочего стола (снег, дождь, песок, листья, марсианская пыльная
буря): прозрачный оверлей,
кучи на кромках окон, реакция на курсор. Rust, одна кодовая база для macOS,
Windows и Linux (X11). Отрисовка — на видеокарте через wgpu или программно, на
процессоре. Описание для людей — в `README.md`, его нужно держать в актуальном
состоянии.

## Команды

Rust установлен через rustup без правки профиля оболочки, поэтому в каждой
новой команде сначала `. ~/.cargo/env`.

```sh
. ~/.cargo/env
cargo test                                            # тесты физики, отрисовки и настроек
cargo build --release                                 # сборка под текущую ОС
cargo check --target x86_64-pc-windows-msvc           # проверка Windows-кода
cargo check --target x86_64-unknown-linux-gnu         # проверка Linux-кода
sh scripts/bundle-macos.sh                            # dist/Snowdrift.app
pkill -f dist/Snowdrift.app/Contents/MacOS/Snowdrift  # остановить запущенную копию
open dist/Snowdrift.app                               # запустить
```

После правки кода: тесты, обе проверки `cargo check --target`, пересборка
бандла, остановить старую копию, запустить новую — иначе пользователь
продолжит видеть старую версию. Останавливать можно только сам «Сугроб».

Сборки без предупреждений компилятора на всех трёх целях — обязательное условие.

## Проверка результата

- **macOS.** Снять скриншот из сессии нельзя (`screencapture` не имеет
  разрешения на запись экрана), поэтому внешний вид проверяет только
  пользователь. После видимого изменения: прямо сказать, что результат не был
  увиден, и попросить посмотреть.
- **Windows и Linux.** Запустить их здесь нельзя вообще. `cargo check`
  подтверждает только компиляцию. Нельзя писать, что версия «работает», пока
  пользователь не запустил её на настоящей системе.

Внешний вид можно увидеть и без экрана: тест `dump_preview` сохраняет кадры
программного растеризатора (`SNOWDRIFT_DUMP=папка cargo test dump_preview --
--ignored`, формат — в `README.md`), а скрипт на python3 без зависимостей
накладывает их на фон и собирает PNG, который открывает инструмент Read.
Скрипт в репозиторий не входит: он пишется на месте в папке для временных
файлов. Это видит только растеризатор, шейдер на видеокарте так не проверить.

Без экрана на macOS можно проверить: процесс жив (`pgrep`), нагрузку
(`ps -o %cpu`), строку `сугроб: отрисовка — …` в stderr при запуске бинарника
напрямую, и что окно-оверлей есть в `CGWindowListCopyWindowInfo` (слой 25).

Чтобы запустить бинарник с другими настройками, не трогая настройки
пользователя, — подменить `HOME` на временную папку с файлом
`Library/Application Support/snowdrift/settings.conf` (например, `gpu=0` для
программного режима). Такой запуск виден пользователю на экране, поэтому он
должен быть коротким и заканчиваться `pkill`.

Любая ошибка в прозрачности закрывает пользователю весь экран. После правок в
отрисовке или в работе с окном первый запуск делать с автозавершением
(`sleep 45; pkill …` в фоне) и предупреждать, что `pkill Snowdrift` — выход.

## Устройство

| Файл | Роль |
| --- | --- |
| `src/materials.rs` | Таблица материалов `Material`: чем снег отличается от дождя, песка и листьев |
| `src/sim.rs` | Вся физика, общая для материалов. Никаких зависимостей от ОС и отрисовки. Тесты здесь же |
| `src/decor.rs` | Украшения на кромках окон (ели, деревья, кактусы, камни), собранные из `Capsule`. Тесты здесь же |
| `src/sim/heap.rs` | Шары, холмики и снеговики, собранные курсором. Подмодуль `sim`, поэтому видит его закрытые поля. Тесты здесь же |
| `src/sky.rs` | Небо: солнце, луна, звёзды. Чистая функция от времени, отдаёт `FlakeLook`. Тесты здесь же |
| `src/clock.rs` | Местное время и дата: `libc::localtime_r` на macOS и Linux, `GetLocalTime` в Windows |
| `src/look.rs` | Фигуры и цвета частиц, куч и неба — общие для обеих отрисовок |
| `src/render.rs`, `src/shader.wgsl` | wgpu: частицы инстансами, кучи треугольниками |
| `src/soft.rs` | Растеризатор на процессоре; тесты здесь же |
| `src/gfx.rs` | `Gfx`: выбор между `Renderer` и программной отрисовкой |
| `src/platform/mod.rs` | Договор, который выполняет каждая платформа |
| `src/platform/{macos,windows,linux}.rs` | Окна, курсор, Dock / панель задач, настройка оверлея |
| `src/tray.rs` | Меню: `tray-icon` на macOS и Windows, `ksni` на Linux |
| `src/settings.rs` | Файл настроек и список интенсивностей `RATES` |
| `src/main.rs` | Окно, цикл кадров, перевод координат ОС в координаты симуляции |
| `swift/` | Прежняя версия только для macOS. Не развивается |

Идентификаторы поверхностей: номер окна — обычное окно, `0` — низ экрана,
`-1` — Dock / панель задач.

## Что важно не сломать

- **Дымка.** У материала может быть `haze` (цвет и прозрачность на весь экран).
  Она — фон кадра: на GPU цвет очистки, на процессоре начальная заливка
  растра. Вырезается по рамкам окон вместе с небом, поэтому `cut_pipeline`
  включается и при `sky_n > 0`, и при `haze[3] > 0`. Прозрачность «дышит» по
  `Sim::haze()`.
- **Ветер.** Один на все материалы, считается в начале `Sim::step`: порывы,
  направление (`WindDir`), сила (`wind_force`). Материал не знает про выбор
  пользователя, он умножает ветер на свой `wind` и добавляет свой постоянный
  снос `wind_bias`, чей знак подстраивается под выбранное направление
  (`bias_of`). Не читать ветер из настроек в обход `Sim`.
- **Меню.** Пункты сгруппированы в подменю: `Submenu` у `tray-icon`, `SubMenu`
  у `ksni`. Группа взаимоисключающих пунктов — `radio` в обеих реализациях.
  Идентификаторы пунктов `tray-icon`: `scene`, `sky`, `place`, `wdir`,
  `wforce`, `rate` плюс номер; префиксы не должны быть началом друг друга.
- **Материалы — это данные.** Различия между осадками задаются только числами
  в `materials.rs`; размеры — множителем `scale` относительно снежинки. Не
  писать в `sim.rs` ветки вида «если дождь, то…»: нужно новое поведение —
  добавить поле в `Material`.
- **Общий код — общий.** Поведение осадков живёт только в `sim.rs`. В
  `platform/` — только получение данных от ОС. Не добавлять в физику `cfg` по
  платформам.
- **Единицы.** Симуляция считает в логических точках, y вниз от левого
  верхнего угла основного экрана. macOS отдаёт точки, Windows и X11 —
  физические пиксели; пересчёт только в `Overlay::point` / `Overlay::rect` по
  константе `platform::PHYSICAL`.
- **Сохранение массы.** Материал не появляется и не исчезает просто так:
  частица при приземлении отдаёт массу столбику, срезанное и сброшенное снова
  становится частицами. Исключения: в режиме непроницаемых окон лишние частицы
  тают, вода высыхает (`evaporate`), брызги дождя массы не несут, при смене
  материала старые кучи улетают за экран.
- **Порядок окон.** `Platform::windows` отдаёт окна от переднего к заднему; на
  этом построены перекрытие и перенос кучи на переднее окно.
- **Подпись macOS-бандла.** `bundle-macos.sh` подписывает с явным требованием
  `designated => identifier "local.snowdrift"`. Без него «ad hoc»-подпись
  привязана к `cdhash` сборки, запись в Универсальном доступе после каждой
  пересборки устаревает (переключатель горит, но не работает) и система
  просит доступ заново. Не убирать `--requirements` и не менять bundle id.
  `request_dock_access` ничего не делает, если доступ уже есть.
- **Никаких разрешений по умолчанию.** Базовая работа не должна требовать ни
  записи экрана, ни Универсального доступа. Он нужен только для Dock на macOS
  и запрашивается из меню.
- **Оверлей прозрачен для мыши** и не должен перехватывать фокус.
- **Прозрачность в Windows** держится на трёх вещах сразу: бэкенд DX12,
  `Dx12SwapchainKind::DxgiFromVisual` и окно с `with_no_redirection_bitmap`.
  Убрать любую — окно станет чёрным.
- **Альфа на macOS.** Metal-слой ждёт цвет, умноженный на альфу, хотя wgpu
  называет режим `PostMultiplied`. Поэтому на macOS `premul` всегда включён.
  Если это сломать, весь экран зальёт белым и пользователь ничего не увидит.
- **Непрозрачная поверхность — отказ от запуска.** Если прозрачный режим
  недоступен, `Renderer::new` возвращает ошибку, а не закрывает экран.
- **Две отрисовки рисуют одно и то же.** Всё про внешний вид (размеры фигур,
  цвета, контур кучи, формула покрытия) лежит в `look.rs`. Формула в
  `look::coverage` и в `shader.wgsl` — одна и та же; меняя одну, менять другую.
  Фигур шесть: `Capsule` (круг и штрих), `Leaf`, `Glow`, `Moon(фаза)`, `Beam`
  (луч-клин солнца). Новая фигура — в `FlakeShape`, в `coverage`, в
  `FlakeShape::code` и в ветках `fs_flake` шейдера.
- **Растеризатор на процессоре** обходит на каждой строке только отрезок
  внутри повёрнутого прямоугольника фигуры (`row_span`), а не весь охватывающий
  квадрат: иначе длинные наклонные лучи слишком дороги. Не возвращать квадрат.
- **Шары и кучи.** Состояние в `Sim::heaps`, поведение выбирает
  `Material::gather` (`Ball` — снег, `Heap` — песок, листья, пыль, `None` —
  вода). В режиме «собирает» (`Sim::gather`) курсор не разбрасывает кучу, а
  создаёт шар; при выключении, смене материала, «стряхнуть всё», падении с
  края и сдвиге окна шары рассыпаются в частицы, масса сохраняется. Любая
  правка столкновений должна оставлять в `collide` либо слияние/постановку,
  либо упор с зазором (иначе цикл столкновений не кончится).
- **Украшения.** Вид — `Material::decor`, не ветка в коде. Строятся из
  `Capsule` (новой фигуры не нужно) и отдаются в общий буфер фигур в порядке
  небо, вырез по окнам, украшения, частицы, кучи; на GPU они лежат в одном
  буфере с частицами, размер `DECOR_MAX`. Положение выводится из номера окна
  (`hash01`), а не хранится: оно должно быть стабильным от кадра к кадру и
  двигаться вместе с окном. Основание стволов сдвинуто на радиус вверх, иначе
  скруглённый конец заходит под кромку.
- **Небо за окнами.** После отрисовки неба по `Sim::window_rects` вырезаются
  прозрачные прямоугольники, и только затем рисуются частицы и кучи. На GPU
  порядок такой: небо, вырезы (`cut_pipeline`, блендинг `REPLACE`), частицы,
  кучи — частицы и небо лежат в одном буфере, их разделяет номер экземпляра
  `sky_n`. Не переставлять: иначе вырез сотрёт и частицы.
- **Небо.** `Sky` не знает про ОС и не читает часы сама: время ей передаёт
  `main.rs` (`set_clock`, раз в `POLL_SLOW`). Рисуется оно под частицами и
  отдаёт не больше `SKY_MAX` фигур — на столько запасён буфер на GPU
  (`render.rs`); увеличивая небо, увеличивать константу.
- **Часы.** Стандартная библиотека не даёт местное время, поэтому оно берётся
  у системы в `clock.rs`. Для Windows этот код проверен только компиляцией.
- **Программный режим на macOS** — это `soft::Canvas` плюс
  `platform::SoftSurface` (картинка в `CALayer`), а не wgpu: у Metal нет
  программного адаптера. В Windows и Linux программный режим — wgpu с
  `force_fallback_adapter`. Строки растра отдаются слою сверху вниз без
  переворота, хотя слой и сообщает `contentsAreFlipped`: переворот уже
  пробовали, осадки шли снизу вверх.
- **API библиотек.** wgpu, winit, tray-icon меняют API между версиями. Перед
  правкой сверяться с исходниками в `~/.cargo/registry/src/`, а не писать по
  памяти.

## Решения по поведению

- При сдвиге окна куча стряхивается сразу. Вариант «снег едет вместе с окном и
  слетает только при резком движении» пробовали и откатили: снег выглядел
  приклеенным.
- Когда окно наезжает на кучу другого окна, она переносится на кромку
  переднего окна, а не стирается.
- При растягивании окна куча остаётся на своём месте на экране.
- При смене материала старые кучи осыпаются и улетают за экран, не смешиваясь
  с новыми.
- Вид осадков по умолчанию выбирается по календарю (северное полушарие).
  Пыльная буря (Mars) в календарь не входит — только вручную.
- Пыльная буря потребовала трёх новых полей `Material` (`wind_bias`,
  `side_spawn`, `haze`) и `streak` для длины штриха; когда обычных чисел
  таблицы не хватает, добавлять поле, а не ветку в физику.
- Пункт «Аппаратное ускорение» должен переключаться на всех системах, в том
  числе на macOS, — ради этого написан собственный растеризатор.
- Меню собрано в подменю (Осадки, Небо, Ветер, Интенсивность): плоский список
  из тридцати с лишним пунктов был слишком длинным.
- Небо по умолчанию — «по времени суток», в правом верхнем углу. Положение
  выбирается в меню (`SkyPlace`): по дуге вдоль верха, левый или правый угол.
  Тело всегда ниже строки меню (центр на 96 pt), под частицами и за окнами.
  Первая версия шла только по дуге и мешала окнам: пользователь попросил угол
  и переключатель.
- Поведение курсора переключается в подменю «Курсор»: «разбрасывает» (как было
  изначально) или «собирает» в шары и холмики (идея — из видео, где шары
  катают и ставят друг на друга в снеговика). Курсор «собирает» по умолчанию.
  Клики и перетаскивание не используются: оверлей прозрачен для мыши, поэтому
  всё делается одним движением курсора.
- Деревья на окнах уменьшены в 4 раза по просьбе пользователя (высота 12–25 pt);
  толщины стволов подогнаны, минимумы в `decor.rs` рассчитаны на такой размер.
- Выбрана общая кодовая база на Rust (см. `docs/multiplatform.md`).

## Соглашения

- Каждое законченное изменение коммитится сразу, вместе с обновлением
  `README.md` и `CLAUDE.md`, не дожидаясь, пока пользователь посмотрит
  результат. Если ему не понравится — исправление идёт следующим коммитом.
- Origin у репозитория пока нет, и пользователь просил пока не пушить. Ничего
  не создавать на GitHub и не отправлять без прямой просьбы.
- Интерфейс, комментарии в коде и документация — на русском. Идентификаторы в
  коде и сообщения коммитов — на английском.
- Новый пункт меню: команда в `tray::Cmd`, поле в `MenuState`, обе реализации
  в `tray.rs`, обработка в `App::command`, строка в таблице «Управление» в
  `README.md`.
- Новый вид осадков: вариант в `Kind` и `KINDS`, константа `Material`, строка
  в таблице видов в `README.md`. Тест `every_material_falls_and_lands`
  подхватит его сам.
- Новая возможность физики сопровождается тестом в `sim.rs`; изменение
  внешнего вида — проверкой в тестах `soft.rs`.
- `target/` и `dist/` — результат сборки, в git не попадают. `Cargo.lock`
  хранится в git.
